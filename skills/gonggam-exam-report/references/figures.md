# 그림 — 그래프·도형·장치도 (정본)

수학·과학 문항의 그림을 MD·리포트로 옮기는 규칙.

> **대부분 이미 만들어져 있다.** `C:\dev\apps\gonggam-math-engine` 이 3,510문항을
> 무손실로 옮기며 이 문제를 먼저 풀었다. **새로 짓기 전에 거기를 먼저 본다.**

---

## 0. 왜 어려웠나 — 목적이 둘이었다

| 목적 | 필요한 것 | 표현 |
|---|---|---|
| 문제를 **다시 찍어내기** | 원본 그대로 | 비트맵 |
| 문제를 **분석하기** (난이도·변인 수) | 무엇이 담겼나 | 구조화된 기술 |
| 문제를 **변형하기** (쌍둥이) | 숫자를 바꾸면 그림도 바뀐다 | 파라미터 → 재드로잉 |

셋을 한 표현으로 풀려니 난해했다. **나누면 각각은 이미 풀린 문제다.**

## 1. 입력 우선순위 — HWP 가 있으면 자르지 않는다

**이 순서를 먼저 확인한다.** 아래로 갈수록 품질이 떨어진다.

| 순위 | 입력 | 그림 처리 | 품질 |
|---|---|---|---|
| **1** | **HWP 원본** | BinData 를 **무손실 추출** — 자르지 않는다 | 원본 그대로 |
| 2 | 텍스트 PDF | 300 DPI 렌더 후 crop | 인쇄 가능 |
| 3 | 스캔 PDF | 같음 + `figure_quality: low` | 확인 필요 |
| 4 | 사진 | 같음 + `figure_quality: low` | 기울기·그림자 |

학교 시험지는 대개 **HWP 로 만들어진다.** 원본을 받을 수 있으면 그게 최선이고,
그때 `crop_figures.py` 는 **쓰지 않는다.**

### HWP 에서 꺼내기 — `gonggam-math-engine/scripts/hwp_reader.py`

- 문단 텍스트의 `0x0B`(확장 컨트롤) 뒤 4바이트가 객체 종류(tbl/gso/eqed)를 말한다.
  **이 자리를 지우면 수식이 문단 끝에 뭉쳐 붙어 문제가 통째로 망가진다.**
- 그림은 태그 85 에 담기고 오프셋 71 이 BinData 번호다 (그 판본 실측).
- 수식은 태그 88(EQEDIT) — `eq2latex.py` 가 LaTeX 으로 바꾼다.

> ⚠ **BinData 는 deflate 로 눌려 있다.** 풀지 않고 저장하면 확장자만 `.png` 인
> 쓰레기가 나온다 — 수학엔진에서 **실제로 1,075개**가 그렇게 만들어졌고,
> 열어 보기 전엔 몰랐다. **저장한 파일은 반드시 열어서 확인한다.**

## 2. 세 층

### ① 원본 비트맵 — 「다시 찍어내기」

문제 원문 MD 가 쓰는 것. 충실도 100%.

- HWP → BinData 추출 (1순위)
- PDF·사진 → `scripts/crop_figures.py` (Claude 가 좌표만 주고 기계가 자른다)
- **빈자리 검사**가 붙어 있다. 좌표가 틀려 백지를 자르면 저장하지 않고 멈춘다

수학엔진의 테이블을 그대로 쓴다 — 스키마를 새로 만들지 않는다.

```sql
figures(item_id TEXT, ord INTEGER, bin_id INTEGER, file TEXT)
```

### ② figure spec — 「분석하기」

난이도축(`subject-axes.md`)이 먹는 데이터. 사람이 세지 않는다.

```json
"figure": {
  "kind": "graph",
  "axes": {"x": "시간 (s)", "y": "속도 (m/s)"},
  "series": 2, "labels": ["A", "B"],
  "given": ["기울기 2", "y절편 3"],
  "reading_required": true,
  "variables": 3
}
```

- 과학 난이도축의 **자료 수·변인 수**가 여기서 자동으로 나온다
- MD 에는 그림과 **나란히** 한 줄로 적는다 — 이미지를 못 보는 곳(검색·다른 스킬)에서도
  뜻이 통해야 한다

### ③ 재드로잉 — 「변형하기」 · `gonggam-math-engine/scripts/figure.py`

**기본이 아니다.** 변형문제·쌍둥이를 만들 때만 쓴다.

> **어느 그림을 다시 그릴지는 AI 가 정하지 않는다.** 종류표와 차단 조건으로 정해져 있다 —
> 정본은 `figure-routing.md`, 판정은 `scripts/figure_route.py`.
> 「다시 그리기 힘든가」를 매번 묻지 않는다. 허용 목록에 없으면 CLEAN 이다.

왜 필요한가 — 수학엔진의 말 그대로다:

> 원본 비트맵을 재사용하면 안 된다. 숫자만 갈린 쌍둥이 옆에 옛날 그림이 붙는
> 순간 **동형이 아니라 오류다.**

좌표를 파이썬 식으로 적고 파라미터로 평가한다.

```python
{"points": {"A": ["0", "b"], "C": ["c", "0"]}}   +   {"b": 4, "c": 8}
```

**안전장치 둘 — 이게 핵심이다.**

| 장치 | 무엇 |
|---|---|
| **위상 불변 `invariants`** | 「반지름을 바꿨더니 두 원이 안 만난다」를 렌더 전에 잡는다. 조건이 깨지면 **렌더를 거부한다** — 그림이 조용히 틀리는 것보다 안 나오는 게 낫다 |
| **등방 스케일** | x·y 를 각각 늘이면 `y=x` 가 45°가 아니다. 배율 하나(min)만 쓰고 남는 쪽은 여백으로 |

이 스킬에서 재드로잉을 새로 만들지 않는다. **`figure.py` 를 부른다.**

## 3. 해설 추출 — 색으로 가른다 · `ink_split.py`

교사용 PDF 는 한 면에 검은 본문과 **청록 풀이**가 겹쳐 인쇄돼 있다.
본문은 이미 HWP 에서 무손실로 뽑았으니 다시 읽을 이유가 없다.

청록만 남기면 — 비전이 읽을 면적이 **1/5**로 줄고, 문제 텍스트를 풀이로 잘못
집어넣는 사고가 사라진다. (실측 200dpi: 청록 `(0,168,216)` 은 `B > G`, 초록 `(0,168,120)` 은 `B < G`)

**2단 조판을 가를 때** — 잉크가 정말 0 인 열에서만 자른다. 최솟값 자리에서
무조건 자르면 줄 꼬리가 옆 단으로 흘러간다(대수 24회 중 **12회 관측**).
0 인 열이 없으면 **자르기를 포기하고 한 장으로 넘긴다.** 넓은 이미지는 불편이지만
잘린 글자는 오류다.

## 4. 다른 과목

| 과목 | 그림의 성격 | 비고 |
|---|---|---|
| 수학 | 도형·좌표평면·그래프 | 재드로잉이 가장 잘 듣는다 (파라미터가 명확) |
| 과학 | 그래프·실험 장치도·회로도 | 장치도는 **재드로잉하지 않는다** — 파라미터화가 안 된다. 원본만 |
| 국어 | `<보기>` 상자·도표 | 대개 텍스트다. 표로 옮긴다 |
| 영어 | 도표·안내문 | 표로 옮긴다. 그림이 필요한 문항이 드물다 |

**장치도·회로도는 원본만 쓴다.** 좌표로 환원되지 않는 그림을 다시 그리면
반드시 틀린다.

---

## 5. 하지 않는 것

1. **HWP 가 있는데 PDF 를 자르지 않는다** — 무손실이 있는데 열화본을 만들 이유가 없다
2. **원본 비트맵을 변형문제에 재사용하지 않는다** — 동형이 아니라 오류가 된다
3. **위상 검사 없이 다시 그리지 않는다** — 붕괴한 그림은 조용히 틀린다
4. **x·y 를 따로 늘이지 않는다** — 기울기가 거짓말을 한다
5. **저장한 파일을 열어 보지 않고 넘어가지 않는다** — 쓰레기 1,075개가 그렇게 생겼다
6. **좌표를 짐작으로 적지 않는다** — `crop_figures.py --pages` 로 먼저 본다
