# 요약본 규격 (정본)

`assets/template_summary.html` 이 지키는 규격이다. **A4 딱 한 장.**
본편 리포트 규격은 `report-schema.md` 가 갖고, 이 문서는 «한 장으로 줄일 때 무엇을 남기고
무엇을 버리는가» 만 정한다.

> 학부모 카톡·문자에 첨부하고, 상담 탁자 위에 올려놓는 종이다.
> **40초 안에 읽힌다**는 전제로 만든다. 못 읽히면 분석이 아무리 정확해도 소용이 없다.

---

## 0. 한 장 원칙

| | |
|---|---|
| 판형 | A4 210×297mm · `@page{size:A4;margin:16mm 14mm}` |
| 본문 폭 | 182mm |
| 본문 높이 | **265mm 고정** (`.sheet{height:265mm}`) |
| 쪽수 | **1쪽.** 2쪽이 되면 발행 불가 |
| 모션 | 없다. 인쇄물이다 |
| 색 | `{{THEME_CSS}}` 가 넣는 변수만 (`--primary` `--accent` `--ink` `--muted` `--line` `--gray-pale` `--primary-pale` `--paper`) |
| 글꼴 | `{{FONT_CSS}}` 가 넣는 `'ReportKR'` 하나 · 굵기 **400 / 700 / 900** 셋 |

**색·글꼴을 값으로 적지 않는다.** 테마(`clean` `gonggam` `mono` `warm`)를 갈아 끼워도
같은 조판이 나와야 한다. 흑백 복사를 거칠 예정이면 `mono` 로 뽑는다.

### 굵기는 셋뿐이다 — 400 · 700 · 900

| 굵기 | 쓰는 곳 |
|---|---|
| **900** | 학교명 · 과목 · 숫자 카드 값 · 난이도 숫자 · 대표 문항 번호/제목 · 총평 첫 줄 |
| **700** | 라벨 · 배지 · 칩 · 캡션 · 강조 어구 |
| **400** | 본문 전부 (발췌 · 이유 · 조건 · 총평 본문) |

**600·800 같은 중간값을 쓰지 않는다.** 동봉 폰트에 없는 굵기는 브라우저가 가장 가까운 쪽으로
말없이 옮긴다 — 800 은 900 으로 올라붙어 **온 종이가 굵어지고 대비가 사라진다.**
(실제로 800 을 스무 군데 쓰고 있었다. 900 이 들어오면서 전부 굵어질 자리였다.)

제목에는 자간 **`-.02em`** 을 준다. 900 은 글자가 굵어 그만큼 서로 붙여야 덩어리로 읽힌다.
**굵기를 바꿔도 조판 높이는 그대로다** — 400·700·900 셋을 다 넣고 다시 재서 확인했다
(머리글 17.0 · 카드 15.8 · 밴드 38.8 · 대표 문항 86.5mm, 바뀐 값 없음).

## 1. 만드는 법

```bash
python scripts/render_report.py report.json out/ --summary              # 배포본
python scripts/render_report.py report.json out/ --summary --internal   # 내부 확인본
```

`--summary` 는 `assets/template_summary.html` 을 쓴다. 그 파일이 없으면 렌더가 **실패한다** —
본편 템플릿으로 슬쩍 대체하지 않는다.
렌더러가 PDF 까지 만들고 **PDF 를 열어 쪽수를 실측**한다. 꼬리말의 쪽 표시는 그 실측값이다.

표본은 `examples/summary.sample.json`. 규격을 고치면 표본도 같이 고치고 렌더를 다시 돌린다.
둘이 갈라지면 규격이 죽는다.

## 2. 데이터 계약

**요약본 입력은 본편 `report.json` 과 같은 파일이다.** 아래 셋만 다르다.

1. `sections` 를 요약본이 아는 다섯 개로 줄인다
   (`overview` `difficulty` `type-chart` `killer` `summary`)
2. `killer` 를 **한 개**로, `types` 를 **상위 세 개**로 잘라서 넘긴다
3. `issues` 와 `next_action` 을 더한다

`items` 는 그대로 둔다. 요약본 템플릿이 직접 읽지는 않지만
**난이도 5칸을 렌더러가 `items` 에서 세고**, 게이트의 데이터 검사가 그것을 본다.

### 2-1. 요약본이 싣는 섹션

| 섹션 키 | 요약본에서 | 쓰는 데이터 |
|---|---|---|
| `overview` | 숫자 카드 4 | `overview.cards[{label,value}]` — **정확히 4개** |
| `difficulty` | 난이도 5단 + 한 줄 설명 | `difficulty.bins[{label,count}]`(자동) · `difficulty.summary` |
| `type-chart` | 많이 나온 유형 | `types[{name,count,points}]` — **상위 3개만** |
| `killer` | 대표 문항 | `killer[{no,title,why,excerpt,choices[],answer,concepts[]}]` — **1개만** |
| `summary` | 왜 갈렸나 + 총평 + 다음 행동 | `difficulty.discriminator` · `overview.highlight` · `summary{quote,desc}` · `next_action` |

**이슈 문항은 `sections` 가 아니라 «데이터» 가 켜고 끈다.** 그 상자만은 SECTION 으로 감싸지
않았다 — `issues` 가 빈 목록이면 저절로 사라진다. 그래서 `sections` 에 `issues` 를 적어도
되고(빈 자리를 따로 두었다) 안 적어도 된다. `report_build.py` 의 `SUMMARY_SECTIONS` 처럼
`issues` 가 없는 목록을 그대로 넘겨도 이슈 상자는 제대로 찍힌다.

섹션 밖(항상 찍히는 것): 로고(`brand.academy` · `brand.logo_path`) · `meta.school`
`meta.grade_label` `meta.term` `meta.scope` `meta.subject` `meta.total_items`
`meta.total_points` · `disclaimer`.

### 2-2. 요약본이 «싣지 않는» 섹션

`items` · `chapter-ratio` · `grade-cut` · `study-plan` · `parent-note` 는
**한 장에 들어가지 않는다.** 본편 리포트에만 있다.

템플릿 맨 아래에 이 다섯 개의 **빈 자리**가 있다. 본편 `sections` 목록을 그대로 넘겨도
렌더가 죽지 않게 하려는 것이고, 넘겨도 **아무것도 찍히지 않는다.**
요약본을 만드는 쪽은 §2-1 표의 다섯 개만 적는 것을 원칙으로 한다.

### 2-3. 요약본 전용 필드

| 필드 | 필수 | 뜻 |
|---|---|---|
| `killer[0].kind` | ✔ | **`객관식` 또는 `서술형`.** 대표 문항의 꼴을 가른다 (§2-4) |
| `killer[0].excerpt` | ✔ | 대표 문항 지문·발문 발췌. **줄바꿈이 그대로 살아난다** (`white-space:pre-line`) |
| `killer[0].choices[]` | ✔ | 선지 문자열 목록. 번호(①②…)는 **적지 않는다** — 템플릿이 1부터 매긴다. **서술형이면 `[]`** |
| `killer[0].conditions[]` | ✔ | 〈조건〉 상자에 들어갈 줄. **객관식이면 `[]`** |
| `killer[0].answer` | ✔ | 객관식이면 **정답 숫자**, 서술형이면 **모범답안 한 줄** |
| `issues` | ✔ | 없으면 **빈 목록** `[]`. 키를 아예 빼면 렌더가 실패한다 |
| `issues[0].kind` | | `복수정답` `조건누락` `범위밖` `배점과다` `유형급변` 다섯 중 하나 |
| `next_action` | ✔ | **학원이 할 일 한 줄.** 학부모가 할 일이 아니라 학원이 할 일을 적는다 |
| `study_plan[]` | | 채움 블록 1순위가 쓴다 (§4-1). 없으면 그 블록을 못 켠다 |
| `parent_note[]` | | 채움 블록 2순위 |
| `difficulty.detail[]` | | 채움 블록 3순위 · `{label,count,points,nos}` |

**선지에 정답을 칠하지 않는다.** 렌더러에 조건문이 없기도 하지만,
무엇보다 **흑백 복사에서 칠은 사라진다.** 정답은 선지 아래 칸에 숫자로만 적는다.

`killer` 에 둘 이상을 넣으면 **대표 문항 상자가 그만큼 반복되어 2쪽이 된다.**
자르는 것은 요약본을 만드는 쪽(`killer[:1]`)이다. 템플릿은 자르지 않는다 —
조용히 버리면 「왜 15번이 안 나왔지」를 아무도 모른다. `issues` 도 같다.

### 2-4. 대표 문항은 두 꼴이다 — 객관식 · 서술형

킬러문항은 기계가 고른다 (난이도 `상` 중 배점 높은 순). 그래서 **배점 높은 서술형이
1순위가 되는 일이 흔하다.** 규칙을 깨서 객관식을 고르게 하지 않는다 — 실제로 가장 많이
갈린 문항이 그것이기 때문이다. **템플릿이 두 꼴을 받는다.**

| | 객관식 | 서술형 |
|---|---|---|
| 발췌 | 지문 | 지문 + 발문 |
| 그 아래 | **선지** ①~⑤ | **〈조건〉 상자** |
| 답 칸 이름표 | 「정답」 | 「모범답안」 |
| `answer` 값 | `"2"` | `"(A) routine   (B) belonging"` |
| 빈 목록 | `conditions: []` | `choices: []` |

**「본문참조」를 학부모가 받는 종이에 찍지 않는다.** `items[].answer` 의 «본문참조» 는
내부 표기다. 서술형 대표 문항의 `killer[0].answer` 에는 **모범답안 한 줄**을 적는다.

**가르는 장치는 빈 목록이다.** 렌더러에 «만약» 이 없으므로, 선지 상자와 조건 상자는
각각 `REPEAT` 가 0번 돌면 **진짜로 빈 칸**이 되고 `:empty` 가 자리째 없앤다.
`kind` 는 답 칸 이름표(「정답」/「모범답안」)와 머리줄 배지에만 쓴다.
그래서 **`choices` 와 `conditions` 는 둘 다 «있어야» 한다** — 안 쓰는 쪽을 `[]` 로.
키를 아예 빼면 `REPEAT 대상이 report.json 에 없습니다` 로 렌더가 멈춘다(조용히 비지 않는다).

## 3. 지면 배분

위에서 아래로 이 순서다. 블록 사이 간격 3.2mm.
실측은 표본 둘(`summary.sample.json` = 객관식, `summary.seosulhyeong.sample.json` = 서술형.
둘 다 발췌 5줄 · 이슈 1개)을 크롬으로 재서 얻은 값이다.

| 블록 | 설계 | 표본 실측 | 내용 |
|---|---|---|---|
| 머리글 | 20mm | **17.0mm** | 학원 로고 · 학교/학년 · 시험명/범위 · 과목 |
| 숫자 카드 4 | 22mm | **15.8mm** | 문항 수 · 총점 · 서술형 배점 · 출처 갈래 |
| 난이도 5단 + 유형 상위 3 | 35mm | **38.8mm** | 좌우 2단. 한 줄씩 가로로 압축 |
| **대표 문항 · 객관식** | 50mm | **81.9mm** | 발문 + 발췌 5줄(27.6) + 선지 5(14.9) + 정답(6.8) + 칩 |
| **대표 문항 · 서술형** | 50mm | **86.5mm** | 발문 + 발췌 5줄(27.6) + 〈조건〉 3줄(23.5) + 모범답안(6.8) + 칩 |
| **이슈 문항** | 35mm | **23.9mm** | 있을 때만. 갈래 배지 + 이유 2줄 + 조건 발췌 |
| 왜 갈렸나 | 18mm | **17.6mm** | 2줄 |
| 총평 + 다음 행동 | 25mm | **26.7mm** | 한 문장 결론 + 총평 + 학원이 할 일 한 줄. **내용 높이 고정** |
| 꼬리말 · 고지 | 10mm | **9.7mm** | 출처 표기 · 추정치 고지 · 쪽 표시 |
| 합 | 215mm | **265.0mm** | 두 꼴 모두 넘침 0.0mm · 1쪽 |

**서술형이 객관식보다 4.6mm 크다.** 〈조건〉 상자(23.5mm)가 선지 다섯 줄(14.9mm)보다
8.6mm 크고, 대신 선지 자리가 통째로 사라져 그만큼 되돌려받기 때문이다.
총평 상자는 두 꼴에서 같은 높이(26.7mm)이고, 차이는 **꼬리말 위 흰 여백**이 흡수한다.
**두 꼴 다 한 장 안에서 끝난다.**

**설계값은 «최소 확보량»이지 고정 높이가 아니다.** 실제 높이는 내용이 정한다.

- 머리글·카드·난이도·대표 문항·이슈·꼬리말 = `flex:0 0 auto` (내용이 높이를 정한다)
- 왜 갈렸나 + 총평 **칸**(`.closing`) = `flex:1 0 auto`
  (**남는 자리를 받되 줄어들지는 않는다** — 아래 «조용한 사고» 참조)
- 그 안의 총평 **상자**(`.final`) = `flex:0 0 auto` — **내용 높이 그대로.**
  남는 자리는 상자 **밖**, 꼬리말 위 흰 여백이 된다 (§4)

**상자를 늘려 자리를 채우지 않는다.** 예전에는 남는 자리를 상자가 먹되 52mm 에서
멈추게 했는데, 그러면 «내용보다 훨씬 큰 빈 파란 상자» 가 남았다 — 흰 종이가 아니라
**빈 강조**다. 파란 바탕이 넓으면 그 자체가 강조인데 정작 강조할 글은 위쪽에만 있다.
「강조가 많으면 강조가 없다」에 걸린다 (수동 검수에서 잡혔다).

남는 자리는 **여유분**이고, 발췌가 6줄로 늘거나 문장이 길어지면 거기서 먼저 깎인다.

### 조용한 사고 — 마무리 칸이 «줄어들면» 겹쳐 찍힌다

`.closing` 을 줄어들 수 있게 두면(`flex:1 1 auto` + `min-height`) 발췌가 길어질 때
그 칸이 **내용보다 작아지고**, 총평 상자가 **꼬리말 위에 겹쳐 찍힌다.**
그런데 쪽수는 그대로 1쪽이라 **게이트도 통과한다** — 겹친 종이가 학부모에게 나간다.
실제로 발췌 8줄에서 그렇게 찍혔다(실측).

그래서 `flex:1 **0** auto` 다. 줄어들지 않으면 넘칠 때 **2쪽**이 되고,
「요약본 1쪽」이 막는다. **조용히 겹치느니 시끄럽게 막히는 편이 낫다.**

## 4. 이슈 문항이 없을 때

`issues` 가 빈 목록이면 그 상자는 **통째로 사라진다** (REPEAT 가 0번 돌기 때문이다).
빈 테두리도, 「해당 없음」도 찍지 않는다. 표본으로 잰 차이는 이렇다.

| 블록 | 서술형 · 이슈 있음 | 서술형 · 없음 | 객관식 · 있음 | 객관식 · 없음 |
|---|---|---|---|---|
| 이슈 문항 | 23.9mm | **0 (사라짐)** | 23.9mm | **0 (사라짐)** |
| 왜 갈렸나 + 총평 칸 | 54.1mm | 81.2mm | 58.8mm | 85.9mm |
| └ 총평 상자 | **26.7mm** | **26.7mm** | **26.7mm** | **26.7mm** |
| 꼬리말 위 흰 여백 | 7.2mm | **34.3mm** | 11.9mm | **39.0mm** |
| PDF | 1쪽 | 1쪽 | 1쪽 | 1쪽 |

**총평 상자는 두 경우에 같은 높이다.** 이슈가 빠져서 생긴 27mm 는 상자가 먹지 않고
**꼬리말 위 흰 여백**으로 남는다. 상자는 「이번 시험이 갈린 곳」 바로 아래에 붙어 있다 —
둘은 한 덩어리인 마무리라서 떼어 놓지 않는다.

상자를 바닥에 붙이고 여백을 그 위에 두는 꼴도 뽑아 봤는데(`margin-top:auto`),
목록과 총평 사이가 벌어져 **마무리가 두 동강으로** 읽혔다. 그래서 쓰지 않는다.

## 4-1. 채움 블록 — 빈 자리를 쓸모로 채운다

34mm 가 비면 학부모 눈에는 **«덜 만든 종이»** 로 보인다. 그래서 자리가 남으면
**쓸모 있는 것**을 넣는다 — 빈 상자로 부풀리는 것과는 다른 이야기다.
억지로 채우는 글은 여전히 금지다. 넣는 것은 **이미 분석해 둔 내용**뿐이다.

| 순위 | 섹션 키 | 블록 | 쓰는 데이터 |
|---|---|---|---|
| 1 | `fill-plan` | **다음 시험까지** — 주차 · 집중할 것 · 할 일 | `study_plan[{week,focus,todo}]` |
| 2 | `fill-home` | 가정에서 도와주실 것 | `parent_note[]` |
| 3 | `fill-difficulty` | 난이도별 문항 — 어디서 갈렸나 | `difficulty.detail[{label,count,points,nos}]` |

`difficulty.detail` 은 요약본 전용이다. `nos` 는 문항 번호를 «6·11·15» 처럼 가운뎃점으로 잇는다.

### 실측 높이 (이 표가 정본이다 — 렌더러는 이 값으로 고른다)

서술형 표본, 발췌 5줄, 이슈 없음(남는 자리 **34.3mm**)에서 잰 값이다.
**블록 하나를 켜면 위에 간격 3.2mm 이 함께 붙는다** — 그래서 필요한 자리는 «높이 + 3.2mm» 다.

| 블록 | 줄 수 | 높이 | 필요한 자리 | 결과 |
|---|---|---|---|---|
| `fill-plan` | 4행 | **29.4mm** | 32.6mm | **1쪽** (여백 1.6mm 남음) |
| `fill-plan` | 2행 | **19.5mm** | 22.7mm | 1쪽 (여백 11.6mm) |
| `fill-home` | 3줄 | **23.7mm** | 26.9mm | 1쪽 (여백 7.4mm) |
| `fill-difficulty` | 5줄 | **33.1mm** | 36.3mm | **2쪽** — 34.3mm 자리엔 안 들어간다 |

**줄 수로 계산하려면** — 세 블록 모두 같은 틀이라 한 식으로 떨어진다.

```
높이(mm) ≈ 9.6 + 4.7 × 줄 수        (fill-plan 은 행마다 점선이 있어 4.95 × 행)
필요한 자리 = 높이 + 3.2
```

- `fill-difficulty` 는 **5줄 고정**이라 33.1mm 다. 객관식 대표 문항 + 이슈 없음
  (남는 자리 **39.0mm**)일 때만 들어간다. 서술형이면 자리가 모자라 켜지 않는다
- 두 블록을 한꺼번에 켜려면 59mm 넘게 남아야 한다 — 그런 경우는 없다.
  **한 번에 하나**라고 보면 된다
- 블록이 하나도 안 켜져도 조판은 그대로다. 이슈 문항이 있는 경우(남는 자리 7.2mm)가 그렇고,
  그때도 1쪽이다 (실측)

**남는 자리를 재는 쪽은 렌더러다.** 템플릿은 켜고 끌 자리(`<!-- SECTION:fill-… -->`)와
위 실측값만 제공한다. 짐작으로 고르지 않는다.

---

**억지로 채우는 글은 넣지 않는다.** 할 말이 없으면 여백이 남는 것이 맞다 —
채움 블록은 **이미 써 둔 분석을 옮겨 붙이는 것**이지, 자리를 메우려고 새로 지어내는 것이 아니다.

## 5. 한도 — 이걸 넘기면 2쪽이 된다

한 장을 지키는 것은 CSS 가 아니라 **글자 수**다.
템플릿은 넘치는 글을 `overflow:hidden` 으로 **감추지 않는다.** 감추면 학부모가 받은 종이에서
문장이 잘린 채 끝나고 아무도 그걸 모른다. 넘치면 2쪽이 되고, 게이트가 막는다.

| 자리 | 한도 | 넘치면 |
|---|---|---|
| `killer[0].excerpt` | **6줄 · 420자** (줄당 약 70자 · 본문 폭 182mm) | 한 줄에 4.7mm. 서술형은 **7줄부터 2쪽** (아래 실측표) |
| `killer[0].choices` | 5개 · 각 40자 | 선지가 세 줄로 접히며 상자가 커진다 |
| `killer[0].conditions` | **3줄 · 각 34자** (서술형) | 조건 상자가 한 줄(7.5mm)씩 커진다. 4줄이면 여유분의 3분의 1을 먹는다 |
| `killer[0].answer` (서술형) | **한 줄 · 40자** | 모범답안 칸이 두 줄로 접힌다 |
| `killer[0].title` | 30자 | 머리줄이 두 줄이 된다 |
| `killer[0].why` | 2줄 (90자) | |
| `killer[0].concepts` | 3개 · 각 8자 | 4개부터 칩이 세 줄로 접힌다 |
| `issues[0].reason` | 2줄 (100자) | |
| `issues[0].excerpt` | 1줄 (60자) | |
| `difficulty.summary` | 1줄 (45자) | |
| `difficulty.discriminator` | 2줄 (90자) | |

| `overview.cards[].value` | 8자 | 카드 숫자가 두 줄로 접힌다 |

### 「6줄」은 **찍힌 줄** 이다 — 원고 줄이 아니다

`report_build.py` 의 `passage_of` 는 **MD 원고의 줄**을 여섯 개 센다. 원고 한 줄이
긴 문단이면 종이에서는 그 한 줄이 대여섯 줄로 접힌다 — 여섯 줄을 지켰는데 2쪽이 나는 길이다.
그래서 한도를 **글자 수로도** 적는다: **약 420자**(6줄 × 70자).
자르는 쪽은 줄 수와 글자 수를 **둘 다** 본다.

### 한도를 넘기면 어떻게 되나 (실측)

발췌를 길게 넣으면 흰 여백을 다 먹고 **넘친다.** 그때 일어나는 일은 이렇다.

- PDF **2쪽.** 둘째 장으로 넘어간 꼬리말이 앞 장 내용과 **겹쳐 찍힌다** —
  글자가 한눈에 사고로 보인다 (PDF 글자를 뽑아 확인했다)
- 쪽 표시도 스스로 **「1 / 2 페이지」**로 바뀐다 — 사고가 종이에 드러난다
- 게이트의 「요약본 1쪽」이 여기서 막는다 (G10 양성 대조가 이 자리를 지킨다)

### 여유분이 얼마나 되나 (실측)

가장 빠듯한 경우는 **서술형 대표 문항 + 이슈 문항 있음**이다 (조건 상자가 선지보다 크다).
발췌를 한 줄씩 늘려 가며 쟀다 — 한 줄이 **4.7mm** 다.

| 발췌 | 대표 문항 | 꼬리말 위 흰 여백 | PDF |
|---|---|---|---|
| 5줄 (표본) | 86.5mm | 7.2mm | 1쪽 |
| **6줄 (한도)** | 91.2mm | 2.5mm | **1쪽** |
| 7줄 | 95.9mm | 없음 (2.1mm 모자람) | **2쪽** |
| 8줄 | 100.7mm | 없음 (6.9mm 모자람) | **2쪽** |

**6줄 한도는 헐겁지 않다 — 딱 마지막 안전한 값이다.** 서술형에서 한 줄만 더 붙으면 2쪽이 된다.
객관식은 선지가 조건 상자보다 4.6mm 작아 그만큼(약 한 줄) 더 버틴다.
그래서 한도를 6줄로 못 박고, 넘치면 **글을 줄인다** — 조판을 늘리지 않는다.
이 표는 `flex:1 0 auto` (줄어들지 않는 마무리 칸)를 전제로 잰 값이다.
줄어들게 두면 7·8줄이 «1쪽» 으로 나오는데, 그건 겹쳐 찍힌 1쪽이다 (§3 조용한 사고).

### 발췌가 길면

**줄이는 것이지 감추는 것이 아니다.** 셋 중 하나를 고른다.

1. 지문의 **판가름 나는 대목만** 남기고 앞뒤를 `…` 로 줄인다 (가장 좋다)
2. 지문 대신 **발문과 선지만** 싣는다. 지문 전체는 본편 리포트에 있다
3. 그래도 길면 그 문항은 요약본의 대표 문항으로 **부적합**하다. 다른 문항을 고른다

원문을 그대로 실어야 하는 자료는 요약본이 아니라 본편 리포트로 보낸다.

## 6. 흑백 대응

학원 문서는 복사기를 거친다. **색만으로 구분하지 않는다.**

- 난이도 5칸 중 `상` `중상` 은 색이 아니라 **테두리 굵기(1.6pt)** 로 세운다
- 대표 문항 = 1.4pt 실선 테두리, 이슈 문항 = 왼쪽 3pt 굵은 선
- 정답·이슈 갈래 배지는 채우지 않고 **테두리 + 굵은 글씨**
- 막대는 테두리가 있어 0% 도 자리가 보인다 (`mono` 테마에선 빗금으로 바뀐다)
- 본문 최소 7.5pt — 그 아래로 내리지 않는다
- **흑백으로 한 번 출력해 본다.** 이게 가장 확실한 검사다

## 7. 템플릿 계약 (템플릿을 고칠 때만 본다)

지시자는 본편과 같다 (`report-schema.md` 끝 표). 요약본만의 약속 넷.

**쪽 표시는 한 군데.** 꼬리말 오른쪽 구석이다. 렌더러가 PDF 를 재서 채우므로
한 장이면 `1 / 1 페이지`, 넘치면 `1 / 2 페이지` 가 찍힌다.
「페이지」라는 낱말을 쓰는 이유는 둘이다 — `render_pdf.py` 가 **스스로 찍는 판형으로 보고
도장을 건너뛰고**, 게이트가 그 표기로 쪽수를 대조한다. 「쪽」으로 바꾸면 게이트가 막는다.
그 칸은 `position:absolute` 라 숫자 폭이 바뀌어도 조판이 밀리지 않는다(쪽수 1패스 수렴).

**`section-title` 클래스를 단 요소 한 개.** 렌더러는 「쪽번호 앞에 섹션 제목이 있어야 한다」를
강제하고, 그 글자를 PDF 에서 찾아 몇 쪽인지 읽는다. 요약본에는 섹션 제목이 없으므로
머리글의 「기출 분석 요약」 배지가 그 역할을 겸한다. **이 class 이름을 바꾸면 렌더가 실패한다.**

**바깥 상자는 `page` 와 `sheet` 두 클래스를 함께 단다.** 게이트가 장 수를 `.page` 로 세고,
조판 규칙(고정 높이·세로 배분)은 `.sheet` 가 갖는다.

**`<!-- INTERNAL -->`** 은 꼬리말의 «발송 전 확인» 네 줄에 쓴다. 배포본에는 찍히지 않는다.

### 7-1. 주석에 적으면 안 되는 것 (두 번 데였다)

게이트는 HTML 을 **글자로** 센다. 주석도 글자다. 그래서 템플릿 주석에

- **쪽 표시 꼴**(숫자 빗금 숫자 «페이지»)을 예로 적으면 → 「총쪽수를 두 가지로 말한다」로 막힌다
- **세는 class 이름을 따옴표째** 적으면 → 「정답이 두 개」처럼 개수 검사가 어긋난다

설명은 낱말로 풀어 쓴다. 지금 템플릿 주석이 그렇게 돼 있다.

### 7-2. 빈 목록이 사라지게 하는 법

선지 상자와 조건 상자는 **여는 태그 바로 뒤에 REPEAT 를 붙여 한 줄로** 쓴다.
줄바꿈이 한 칸이라도 남으면 목록이 비어도 그 칸이 «빈 문자열이 아닌» 것이 되어
`:empty` 가 듣지 않고 **빈 테두리가 인쇄된다.**

### 7-3. 총평 상자 안에 가로 구분선을 긋지 않는다

「다음 행동」 줄을 가로선으로 나눴더니 상자 안에 긴 가로줄이 셋이 되어,
게이트의 **«표 머리글» 검사가 총평 상자를 표로 잘못 읽고 막았다.**
지금은 이름표를 테두리 칩으로 세워 구분을 대신한다.

- [ ] **총평 상자가 꼬리말을 덮지 않았는가** — 겹침은 쪽수로 안 잡힌다. 눈으로 본다

- [ ] 숫자마다 근거가 붙어 있는가 (`disclaimer` 에 추정치 고지)
- [ ] 학생 이름·개인정보가 없는가 — 요약본은 여러 집에 같은 장이 나간다
- [ ] 불안을 자극하는 문장이 없는가 (`korean-writing`)
- [ ] 발췌가 6줄 이내인가

## 9. 요약본 데이터를 «만드는 쪽» 에 거는 약속

`report_build.py --summary` 가 지켜야 할 것. 2026-09-21 기준으로 **아래는 모두 맞춰져 있다.**

| 약속 | 지금 | 안 지키면 |
|---|---|---|
| `killer` 를 1개로 자른다 | ✔ `KILLER_SUMMARY = 1` | 상자가 반복되어 2쪽 |
| 발췌를 6줄 **· 420자**로 자른다 | ✔ 줄 수와 글자 수를 둘 다 본다 | 원고 한 줄이 긴 문단이면 종이에서 접혀 2쪽 (§5) |
| `issues` 를 1개로 자른다 | ✔ `ISSUES_SUMMARY = 1` | 상자가 반복되어 2쪽 |
| `types` 를 상위 3개로 자른다 | ✔ `TYPES_SUMMARY = 3` | 막대가 일곱 줄 — 밴드가 커져 2쪽 |
| `next_action` 을 채운다 | ✔ | `{{next_action}}` 이 남아 **렌더가 실패한다** |
| `killer[0].kind` 를 `객관식`/`서술형` 으로 준다 | ✔ | `{{kind}}` 가 남아 렌더 실패 |
| `conditions` 를 항상 준다 (객관식이면 `[]`) | ✔ | `REPEAT 대상이 없습니다` 로 렌더 실패 |
| 서술형이면 `answer` 에 **모범답안 한 줄** | ✔ 없으면 빌더가 먼저 막는다 | 학부모 종이에 **「본문참조」**가 찍힌다 |

### 채움 블록을 켜는 쪽에 (렌더러 담당)

`fill-plan` · `fill-home` · `fill-difficulty` 는 **렌더러가 남은 높이를 재서 켠다.**
§4-1 실측표가 그 판단의 정본이다. 셋 다 `SECTION_NEEDS` 에 없으므로
빌더가 `sections_summary` 로 받으려면 아래를 더해야 한다.

| 섹션 | 필요한 데이터 |
|---|---|
| `fill-plan` | `study_plan` |
| `fill-home` | `parent_note` |
| `fill-difficulty` | `difficulty.detail` |

### 아직 열려 있는 것 하나 (게이트 담당)

`gate_check.py` 의 **「대표 문항 속살」** 이 선지 두 개 이상을 요구한다
(`k-excerpt` 1 · `k-ans` 1 · `k-choice` ≥ 2). 서술형 대표 문항은 선지가 **없는 것이 정상**이라
이 검사가 막는다 — 실측으로 확인했다(객관식 표본은 게이트 전부 통과, 서술형 표본은 이 한 건만 차단).

고칠 자리는 «선지 ≥ 2» 가 아니라 «**선지 ≥ 2 또는 조건 ≥ 1**» 이다.
조건 줄의 class 이름은 `cond` 다.

### 이름 — 꼬리칸은 «요약본»

파일 이름의 **«요약본»** 이 게이트가 요약본을 알아보는 표다 (`gates.md` §5).
공용 어휘(`gonggam-material-studio/assets/filename_check.py` 의 `TAIL`)에 그 낱말이 들어갔고
렌더러도 그 꼬리칸을 쓴다 — 이름과 실물이 이어져 있다.
발췌가 12줄인 2쪽 산출물을 게이트에 넣으면 「요약본 1쪽」과 「쪽번호 장마다 일치」가
**둘 다 막는 것**을 확인했다.
