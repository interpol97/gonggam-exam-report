# 그림 경로 규격 — 다시 그릴지 원본을 쓸지

**이 판단은 AI 가 하지 않는다.** `scripts/figure_route.py` 가 표를 보고 정한다.

---

## 0. 왜 규격으로 박는가

「다시 그리기 힘든가」는 **열린 질문**이다. 열린 질문은 물을 때마다 답이 달라진다.
같은 회로도를 어제는 그리고 오늘은 안 그리면, 그 자료는 믿을 수 없다.

그래서 질문을 바꾼다.

> ✗ 「이 그림은 다시 그리기 힘든가?」 — 끝이 없다
> ✓ 「이 그림이 **허용 목록**에 있는가?」 — 셀 수 있다

**재드로잉은 화이트리스트다.** 목록에 없으면 원본을 정리해 쓴다.
「힘든 것」은 정의할 수 없지만 「쉬운 것」은 열두 줄이면 적힌다.

그리고 **기본값이 안전한 쪽**이다 — 판정이 애매하면 저절로 CLEAN 으로 떨어진다.

### 길 셋

| 길 | 무엇 | 도구 |
|---|---|---|
| **AS-IS** | **원본을 그대로 싣는다** | (없음 — 손대지 않는다) |
| **CLEAN** | 원본을 깨끗이 만들어 제자리에 꽂는다 | `clean_figure.py` |
| **REDRAW** | 파라미터에서 다시 그린다 | `math-engine/scripts/figure.py` |
| **TABLE** | 그림이 아니라 표다 — 마크다운 표로 | (수작업) |

### ★ CLEAN 은 «사진·스캔» 에만 쓴다 (2026-09-23)

**이미 깨끗한 그림은 원본 그대로 싣는다.** HWP 에서 뽑은 것, 직접 그린 것,
PDF 에서 잘라낸 벡터 — 전부 AS-IS 다. CLEAN 을 거치면 **망가진다.**

과학 목업에서 드러난 자리 —

| 무엇 | 원본 | CLEAN 을 거친 뒤 |
|---|---|---|
| 광합성 막대그래프 | 초록 막대·눈금선 | **막대 속이 비고 흑백** — 자료가 사라졌다 |
| 성도(밤하늘) | 검은 바탕에 흰 별 | **통째로 뒤집혀** 별자리가 없어졌다 |
| 파일 크기 | 23KB | **72KB** — 2값화가 노이즈를 더했다 |

성도는 더 나쁘다. 잉크 비율이 34.9% 로 **오히려 늘어** 「거의 비었습니다」 검사에
안 걸린다 — **망가진 채로 통과한다.** 과학·사회에는 어두운 바탕 그림(성도·전자현미경·
형광 사진)이 흔하고, **색이 곧 자료인 그림**(리트머스·BTB·불꽃 반응·지시약)도 흔하다.
`clean_figure.py` 는 언제나 흑백으로 읽으므로 그런 그림에서는 정보를 지운다.

가르는 자리는 하나다 — **「사람이 찍거나 스캔한 것인가」.** 아니면 손대지 않는다.

> MD 의 `![…](…)` 가 **무엇을 가리키는지** 보라. CLEAN 산출물을 가리키면
> 그 판이 종이에 실린다. 원본 폴더를 가리켜야 한다.

## 1. 종류표 (정본)

`kind` 는 **닫힌 목록**이다. 여기 없는 값을 쓰면 무조건 CLEAN 으로 떨어진다.

| kind | 길 | 왜 |
|---|---|---|
| `coord-graph` | **REDRAW** | 좌표평면·함수 그래프 — 식으로 환원된다 |
| `plane-geometry` | **REDRAW** | 평면도형(원·삼각형·다각형) — 점 좌표로 환원된다 |
| `number-line` | **REDRAW** | 수직선 — 점과 눈금뿐이다 |
| `stat-chart` | **REDRAW** | 막대·꺾은선·원그래프 — 수치에서 나온다 |
| `solid-geometry` | CLEAN | 입체도형 — 투영각이 달라지면 다른 그림이 된다 |
| `apparatus` | CLEAN | 실험 장치도 — 좌표로 환원되지 않는다 |
| `circuit` | CLEAN | 회로도 — 기호 배치가 규약이다 |
| `map` | CLEAN | 지도 — 지형을 다시 그릴 수 없다 |
| `photo` | CLEAN | 사진·사료·유물 — 재현 대상이 아니다 |
| `diagram` | CLEAN | 개념도·흐름도 — 배치가 곧 내용이다 |
| `handwriting` | CLEAN | 손글씨 — 원본이 곧 자료다 |
| `mixed` | CLEAN | 섞였다 — 섞이면 원본이 안전하다 |
| `table-image` | TABLE | 그림으로 들어간 표 |

**REDRAW 넷의 공통점** — `figure.py` 가 아는 어휘 여덟으로 그려진다:
축 · 곡선 · 선분/꺾은선 · 원 · 채움 · 눈금/직각표시 · 점 · 라벨.
그 밖의 것이 하나라도 있으면 그릴 수가 없다.

## 2. 차단 조건

REDRAW 후보라도 **하나라도 걸리면 CLEAN** 이다. 전부 «보면 아는» 사실이다 — 판단이 아니라 관찰이다.

| 표시 | 걸리는 때 |
|---|---|
| `purpose_is_original` | **문제 원문을 옮기는 중이다** |
| `has_photo_texture` | 사진·음영·질감이 있다 |
| `has_handwriting` | 손글씨가 있다 |
| `copyrighted_art` | 출판사 삽화·저작물이다 — 재현이 곧 2차 저작 |
| `labels_over_8` | 라벨이 8개를 넘는다 |
| `no_invariants` | 위상 조건을 하나도 적을 수 없다 |
| `no_spec` | `figure_spec` 이 없다 |

### ★ 가장 중요한 한 줄

> **문제 원문 MD 는 언제나 CLEAN 이다.**

재드로잉은 **변형문제를 만들 때만** 쓴다. 원문을 옮기는 길에서는 선택지가 아니다.
이 한 줄이 「원문이 원본과 다르면 어쩌나」라는 걱정을 통째로 없앤다.
판정이 필요한 자리 자체가 변형문제 경로로 좁혀진다 — 그쪽은 어차피 검증을 거친다.

## 3. 최종 확정은 기계가 한다

경로표를 통과해도 **REDRAW 는 아직 확정이 아니다.**

```
경로표 통과  →  figure_spec 작성  →  figure.py 렌더
                                        ├ 위상 조건 통과 → REDRAW 확정
                                        └ 위상 조건 위반 → CLEAN 으로 내려감
```

`figure.py` 의 `invariants` 가 「반지름을 바꿨더니 두 원이 안 만난다」를 렌더 전에 잡는다.
**그림이 조용히 틀리는 것보다 안 나오는 게 낫다.**

즉 재드로잉은 두 관문을 지난다 — 표(어떤 종류인가)와 기계(정말 성립하는가).
AI 의 「될 것 같다」는 어느 관문에도 들어가지 않는다.

## 4. 쓰는 법

```bash
python scripts/figure_route.py figures.json
```

```
  3    coord-graph      → REDRAW  좌표평면·함수 그래프 — 식으로 환원된다
  14   apparatus        → CLEAN   실험 장치도 — 좌표로 환원되지 않는다
  26   table-image      → TABLE   그림으로 들어간 표
  31   우주선그림          → CLEAN   모르는 종류 — 목록에 없으면 원본을 쓴다
```

**AI 가 하는 일은 `kind` 와 차단 표시를 적는 것까지다.** 길은 표가 정한다.

## 5. 「아마도」는 버리지 않고 쌓는다

화이트리스트만 두면 목록이 **영원히 자라지 않는다.** 모르는 종류는 늘 CLEAN 으로
떨어지고, 아무도 그걸 다시 보지 않는다. 그러면 규격은 굳는 게 아니라 **썩는다.**

그래서 애매한 건은 대기열에 적는다. **적는 것은 결정이 아니다** —
이번 작업은 그대로 CLEAN 으로 가고 기록만 남는다. 막히는 일이 없다.

> ★ **「아마도」를 사람이 선언하지 않는다.** 판정기가 자동으로 넣는다.
> AI 가 «이건 아마도 될 것 같은데» 라고 말할 자리를 만들지 않는다.

### 무엇이 들어가나

| 들어감 | 안 들어감 (`SETTLED`) |
|---|---|
| 목록에 없는 `kind` | `purpose_is_original` — 원문은 규격이 바뀌어도 답이 같다 |
| 위상 조건을 못 적음 | `copyrighted_art` — 저작물은 기술 문제가 아니다 |
| 라벨 8개 초과 · spec 없음 · 질감 · 손글씨 | |

「더 볼 것이 없는」 것은 쌓아 봐야 검토 대상이 아니다. 대기열을 소음으로 채우지 않는다.

```
data/figure-candidates.jsonl     쌓이는 곳 (지우지 않는다 — 횟수가 근거다)
data/figure-kinds-denied.json    박아 둔 것 (같은 질문을 또 하지 않기 위해)
```

### 세 상태

| 상태 | 뜻 | 다음 |
|---|---|---|
| **대기** | 5건 미만 | 아무것도 안 한다. 우연히 한두 번 나온 것으로 규격을 바꾸지 않는다 |
| **검토** | 5건 이상 | `--check <종류>` 로 승격 절차를 연다 |
| **박힘** | 승격 실패 | 다시 검토하지 않는다. 새 근거가 있을 때만 `denied` 에서 지운다 |

```bash
python scripts/promote_kind.py                 # 쌓인 것을 본다
python scripts/promote_kind.py --check <종류>   # 승격 조건을 잰다
python scripts/promote_kind.py --deny <종류> "이유"
```

---

## 6. 목록을 늘릴 때 — 승격은 증거로만

검토 대상이 되어도 **자동으로 올라가지 않는다.** 셋을 다 갖춰야 한다.

| | 조건 | 누가 |
|---|---|---|
| ① | 같은 종류가 **5건 이상** 쌓였다 | 기계가 센다 |
| ② | 표본 **3건**으로 `figure_spec` 을 실제로 썼다 | 사람이 한다 |
| ③ | 셋 다 위상 검사를 통과하고 **원본과 눈으로 대조**해 합격했다 | 기계 + 사람 |

통과하면 `figure_route.py` 의 `KINDS` 와 **이 문서의 표를 같이** 고친다 — 규격은 한 벌이다.

하나라도 «아마도» 면 올리지 않고 **박는다.** 이유를 적어서 박는다:

```bash
python promote_kind.py --deny 우주선그림 "좌표로 환원 안 됨. 표본 3건 중 2건이 위상 조건을 못 적음"
```

박아 두는 까닭은 분명하다 — **같은 질문을 여섯 달 뒤에 또 하지 않기 위해서다.**
「지난번에 안 됐던 것 같은데」로 시간을 쓰지 않는다.

**목록은 늘리기 어려워야 한다.** 쉽게 늘어나는 화이트리스트는 화이트리스트가 아니다.
다만 **늘어날 길은 있어야 한다.** 길이 없으면 규격이 아니라 벽이다.
