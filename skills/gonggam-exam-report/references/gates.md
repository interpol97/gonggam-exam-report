## 0. 철학

> **경고하지 않는다. 막는다.**

옛 스킬은 수식이 0개로 렌더돼도 「성공」을 찍었다. 그래서 규칙은 셋이다.

1. **0개를 재고 통과하지 않는다.** 잴 것을 못 찾으면 그 자체가 결함이다
2. **조용히 건너뛰지 않는다.** 못 잰 것은 이름을 불러 말한다 —
   차단이거나, 「무엇을 못 쟀는지」를 적은 주의다. 말없는 통과는 없다
3. **검사가 눈감을 수 있는 자리를 의심한다.** 짝 파일이 없을 때, 목록이 비었을 때,
   인자가 안 들어왔을 때 — 게이트가 통과를 찍던 자리가 전부 여기였다

### 주의(경고)로 남기는 것은 이 셋뿐

| 주의 | 왜 차단이 아닌가 |
|---|---|
| `PDF 없음` | 렌더 전에 데이터만 보려고 돌릴 수 있다. **대신 못 잰 조판 검사를 전부 이름으로 적는다** |
| `report.json 미검사` · `MD 대조 미실시` | 인자를 안 준 것이다. **무엇을 못 쟀는지 적는다** |
| `표지 채움률 면제` · `채움률 잴 장 없음` | 잴 대상이 구조적으로 없다. **면제한 장 번호를 적는다** |
| `밀려서 생긴 여백` | 여백이 **규칙이 제대로 작동한 결과**다 (§ 4). **장 번호·남은 자리·덩어리 높이를 적는다** |

## 2. HTML

| 검사 | 차단 조건 |
|---|---|
| 빈 자리 없음 | `{{…}}` 가 남았다 |
| **섹션 제목 존재** | `class="section-title"` 제목을 **하나도** 못 찾았다 | ← 요약본은 이 넷 대신 § 5-1 을 받는다 |
| 섹션 번호 연속 | 결번·중복 |
| 한 섹션 = 한 번호 | 같은 제목이 두 번호를 쓴다 |
| **섹션 수 = 제목 수** | `sections` 개수 ≠ 찍힌 제목 개수 (섹션이 조용히 사라졌다) |
| **장수 표기 존재** | `<meta name="gonggam:pages">` 도 «N / M 페이지» 도 없다 |
| **총쪽수 표기 하나** | 쪽 표시들이 서로 다른 총쪽수를 말한다 |
| **총페이지 일치** | `meta` 실측 장수 ≠ 쪽 표시의 총쪽수 |
| **섹션 시작쪽 범위 · 차례** | 시작쪽이 1~총쪽수 밖이다 / 섹션이 뒤로 갔다 앞으로 온다 |
| 동봉 폰트 삽입 | `@font-face` · `ReportKR` 이 없다 |
| 외부 의존 없음 | CDN·웹폰트 링크가 남았다 |
| 금지 문구 없음 | 「100%」「무조건」「보장」「1위」「적중률」… |

### HTML 안에서 «장» 을 세지 않는다

2패스 쪽나눔으로 바뀐 뒤 **HTML 에는 장이라는 요소가 없다.** 섹션이 그냥 흐르고
장은 인쇄할 때 생긴다. `.page` 를 세어 「표기 = .page + .cover」를 보던 옛 모형은
표기 6 ≠ 실제 1 로 **구조적으로 통과할 수 없다.** 그래서 이렇게 바꿨다.

- **HTML 안에서는** 저희끼리 어긋나지 않는지만 본다 (위 표의 넷)
- **진짜 대조는 PDF 와 한다** — § 3 「표기 쪽수 = 실제 쪽수」가 `meta` 실측값과
  쪽 표시를 **둘 다** PDF 실제 장수와 맞춰 본다
- 표기가 하나도 없으면 «대조 안 함» 이 아니라 **차단**이다. 못 재게 된 것을 통과로 바꾸지 않는다
- **«0쪽» 이 나오면 렌더 중간 상태다.** 2패스 렌더는 자리표(`content="0"` · `0 / 0 페이지`)를
  먼저 써 두고 나중에 실측값으로 덮는다. 그 사이에 게이트를 돌리면
  「meta 실측 0쪽 ≠ PDF 실제 6쪽」이 뜬다. **막는 것이 맞다** — 0쪽이라 적힌 HTML 은
  내보낼 것이 못 된다. 메시지가 그 까닭을 말해 주니 렌더가 끝난 뒤 다시 재면 된다.
  **렌더와 게이트를 동시에 돌리지 않는다**

### 주석은 세지 않는다

`<!-- … -->` 는 **사람이 읽는 글이지 종이에 찍히는 글이 아니다.** HTML 검사는 전부
주석을 걷어낸 뒤에 센다 (`<style>`·`<script>` 와 같은 자리다).

안 걷으면 템플릿에 적어 둔 설명이 검사에 걸린다. 실제로 세 번 헛돌았다 —
주석의 «1 / 2 페이지» 예시가 진짜 쪽 표시로 잡혀 「총쪽수를 둘로 말한다」,
주석에 따옴표째 적은 `k-ans` 가 진짜 요소로 세어져 「정답이 2개」.
템플릿 담당이 주석 문구를 바꿔 우회했지만, **우회는 다음 사람에게 같은 함정을 남긴다.**
빈 자리·금지 문구·블록 수·쪽 표시·섹션 제목 — 전부 주석을 걷고 센다.

## 3. PDF — 파일

| 검사 | 차단 조건 |
|---|---|
| PDF 형식 · 페이지 존재 | 머리가 `%PDF-` 가 아니다 / 페이지 0 |
| 크기 정상 | 2쪽 이상은 20KB, 1쪽은 8KB 미만 (동봉 폰트만 19KB 라 쪽수에 맞춰 눈금을 고른다) |
| **짝 HTML 존재** | 같은 이름의 `.html` 이 없다 → 쪽수를 대조할 수 없으니 **막는다** |
| 쪽수 표기 존재 | HTML 에 «N / M 페이지» 가 없다 |
| 표기 쪽수 = 실제 쪽수 | HTML 표기 ≠ PDF 실제 쪽수 |
| **HTML 마다 PDF** | PDF 가 하나라도 있는데 PDF 없는 HTML 이 있다 (그 산출물의 조판을 통째로 못 잰다) |

## 4. PDF — 조판 (PyMuPDF 로 실제로 열어서 잰다)

PyMuPDF 가 없으면 **차단한다.** 못 재는 것을 통과로 바꾸지 않는다 (`pip install pymupdf`).

| 검사 | 차단 조건 | 무엇을 막나 |
|---|---|---|
| **제목만 있는 장 없음** | 제목과 **다음 제목 사이**에 본문이 한 줄(24pt)도 없다 | 제목만 덩그러니 남은 섹션 |
| **홀로 남은 제목 없음** | 제목이 상자의 아래 15% 에 있고 따라온 줄이 2줄 미만 | 장 끝에 홀로 떨어진 섹션 제목 |
| **표 머리글 있음** | 그 장에 표 행 구분선이 있는데 그 위에 머리글 띠가 하나도 없다 | 표가 이어지는 장에서 머리글이 빠진 것 |
| **섹션 시작쪽 일치** | HTML 이 「N번 섹션은 P쪽」이라 적었는데 PDF P쪽에 그 제목이 없다 | 쪽나눔이 실제와 어긋난 것 (옛 `.page` 세기의 후임) |
| **채움률 40% 이상** | 마지막 장·표지를 뺀 어느 장이든 세로 채움률 < 40% **이면서** 그 여백이 밀려서 생긴 것이 아니다 | 짧은 섹션이 한 장을 통째로 먹는 게으름 |
| **쪽번호 장마다 일치** | 쪽번호 없는 장 / 표기 번호 ≠ 실제 장 / 표기 총쪽수 ≠ 실제 | 앞 장이 넘쳐 흘러나온 장 = 경계에서 갈린 내용 |
| **본문 살아남음** | HTML 에 있던 12자 이상 글 토막이 PDF 에 없다 | 상자가 잘라 먹은 글, 경계에서 반쪽 난 블록 |
| 내용 잘림 없음 | 글자가 인쇄 상자 밖에 있다 | (크롬은 상자 밖을 지우므로 거의 안 걸린다 — 실제 검사는 «본문 살아남음») |

### 어떻게 재나

- **본문 상자** — 페이지 전체를 덮는 바탕(인쇄 영역)을 잉크에서 뺀다.
  안 빼면 어느 장이나 93% 가 나와 채움률 검사가 통째로 무의미해진다
- **채움률 면제 — 밀려서 생긴 여백**
  카드는 `break-inside: avoid` 라 반으로 잘리지 않는다. 남은 자리에 안 들어가면
  **통째로 다음 장으로 밀리고** 앞 장 아래에 여백이 남는다. 그건 규칙이 제대로 작동한
  결과지 게으른 조판이 아니다. 같은 자로 벌하면 사람은 **카드를 자르는 쪽으로 도망간다.**
  그래서 이렇게 가른다:

  | | 잰 것 | 판정 |
  |---|---|---|
  | 밀려서 생긴 여백 | 다음 장 **첫 불가분 덩어리 높이** > 이 장 **남은 자리** − 24pt | **주의** (채움률에서 뺀다) |
  | 게으른 여백 | 그 덩어리가 들어가고도 남았다 | **차단** |

  첫 덩어리는 「맨 위에 앉은 카드(테두리·바탕이 있고 높이 40pt 이상, 너비 40% 이상)」,
  카드가 없으면 「첫 20pt 빈 줄까지」로 잰다. 24pt 를 봐 주는 것은 재는 값이
  «그려진» 높이라 바깥 여백이 빠져 있기 때문이다.
  면제한 장은 **번호·남은 자리·덩어리 높이를 적어** 주의로 내보낸다 — 말없이 빼지 않는다.
- **채움률** — (가장 아래 잉크 − 가장 위 잉크) ÷ 본문 상자 높이.
  **마지막 장은 뺀다**(끝 장은 남는 게 정상). **표지도 뺀다** — 쪽번호가 없는 첫 장을
  표지로 보고 면제하되, 면제했다는 사실을 주의로 **반드시 적는다**
- **표** — 고른 간격으로 이어지는 가로줄 **셋 이상** = 표.
  줄간격 상한을 **고정값으로 두지 않는다** — 그 표의 가장 좁은 간격(한 줄짜리 행)을
  기준으로 삼고 그 **정수배(세 줄까지)** 면 같은 표로 본다.
  45pt 로 못 박았더니 두 줄짜리 행(56pt)에서 한 표가 두 무리로 쪼개졌고,
  두 번째 무리에 머리글을 요구해 **머리글이 있는데도 막았다.**
  가로줄이 둘뿐이면 표로 보지 않는다 — 「고른 간격」이라 할 근거가 없고,
  상관없는 상자 테두리 둘을 표로 오해한다
- **머리글** — «진한 색 띠 + 그 안의 흰 글씨 + 표 너비의 40% 이상».
  막대그래프·난이도 배지는 흰 글씨가 없거나 너비가 모자라 머리글로 세지 않는다.
  판정은 **장 단위**다 — 막는 것은 「표 행만 있고 머리글이 없는 장」이지
  「행 무리마다 머리글이 붙었는가」가 아니다
- **제목 아래** — 다음 제목까지로 끊어서 본다. 흐름 조판에서는 한 장에 섹션이 여럿 오므로,
  안 끊으면 뒤 섹션의 본문이 앞 제목의 본문으로 보여 **제목만 남은 섹션을 통과시킨다**
- **본문 살아남음** — HTML 의 `<body>` 에서 태그를 걷어내 12자 이상 토막을 뽑고,
  공백을 지운 채 PDF 전체 텍스트에 그 토막이 있는지 본다.
  크롬은 인쇄 영역을 넘긴 내용을 **말없이 지우므로** 좌표만 봐서는 아무 일도 없어 보인다

## 5. 요약본

규격의 정본은 `references/summary-spec.md` 다. 아래는 게이트가 그것을 어떻게 재는지다.

**요약본을 알아보는 법 — 이름 또는 조판.** 파일 이름에 `요약본` 이 있거나,
HTML 에 요약본 템플릿의 바깥 상자 `class="page sheet"` 가 있으면 요약본으로 잰다.
이름만 보면 꼬리칸이 «배포본» 으로 잘못 붙은 요약본이 1쪽 검사를 통째로 피해 간다
(summary-spec § 9). **둘이 갈리면 그 사실 자체를 막는다** — 게이트는 요약본으로 재는데
학부모는 본편인 줄 알고 받는 종이가 생기기 때문이다.

| 검사 | 차단 조건 |
|---|---|
| 요약본 1쪽 | PDF 가 2쪽 이상. 메시지에 현재 쪽수와 «원문 줄 수를 줄이세요» 를 담는다 |
| **요약본 이름** | 요약본 조판인데 이름에 «요약본» 이 없다 |
| **요약본 조판** | 이름은 요약본인데 요약본 템플릿으로 찍히지 않았다 |

- 요약본은 **표지를 붙이지 않는다.** 붙이면 그것만으로 2쪽이 되어 막힌다
- PDF 가 아직 없으면 `PDF 없음` 주의에 **요약본 이름을 적어서** 내보낸다 —
  쪽수를 못 쟀다는 사실이 보이게 한다

### 5-1. 요약본은 「섹션 제목」 넷 대신 이것을 받는다

요약본은 A4 한 장에 **번호 없는 블록**으로 짠다. 번호 붙은 섹션 제목이 없으니
§ 2 의 「섹션 제목 존재 · 섹션 번호 연속 · 한 섹션 = 한 번호 · 섹션 수 = 제목 수」를
받을 수 없다. **그렇다고 건너뛰지 않는다** — 건너뛰면 그게 바로 「0개를 재고 통과」다.
대신 요약본이 **반드시 담아야 하는 것**을 잰다 (summary-spec § 2-1 · § 5).

| 검사 | 차단 조건 | 무엇을 막나 |
|---|---|---|
| **요약본 표제 하나** | `class="section-title"` 요소가 1개가 아니다 | 렌더러가 쪽수를 읽는 자리가 사라지거나 둘이 된 것 (spec § 7) |
| **요약본 필수 블록** | 머리글·숫자 카드·난이도 5단·유형 막대·대표 문항·총평·꼬리말 중 하나라도 없다 | 한 장에서 블록이 통째로 빠진 것 |
| **숫자 카드 4개** | `overview.cards` 가 4개가 아니다 | 카드 줄이 접혀 조판이 밀리는 것 |
| **난이도 5칸** | 난이도 칸이 5개가 아니다 | 5단이 아닌 분포 |
| **유형 상위 3** | 유형 막대가 0줄이거나 4줄 이상 | 「상위 3」이라 써 놓고 일곱을 실어 2쪽이 되는 것 (spec § 9) |
| **대표 문항 하나** | `killer` 상자가 1개가 아니다 | 상자가 반복되어 2쪽이 되는 것 |
| **이슈 문항 하나까지** | `issue` 상자가 2개 이상 | 〃 (이슈 0개는 정상 — 상자째 사라진다) |
| **요약본 한 장** | `.page` 가 1개가 아니다 | |
| **대표 문항 속살** | 발췌·정답이 없거나, **선지(2개 이상)도 조건(1개 이상)도** 없다 | 대표 문항 상자가 빈 채 나가는 것 |
| **발췌 한도** | 발췌가 6줄 또는 420자를 넘는다 | **2쪽이 되기 전에** 막는다. 한 장을 깨는 가장 흔한 자리 (spec § 5) |

발췌 한도를 글자 수로도 재는 이유: 「6줄」은 **찍힌 줄**이다. 원고 한 줄이 긴 문단이면
종이에서 대여섯 줄로 접힌다 — 줄 수만 지키고 2쪽이 나는 길이 그것이다.

**대표 문항은 두 꼴이다.** 객관식은 선지(`k-choice`), **서술형은 〈조건〉(`cond`)** 을 싣는다.
킬러는 기계가 배점 순으로 고르므로 8점짜리 서술형이 1순위가 되는 일이 흔하다 —
선지만 요구하면 멀쩡한 서술형 요약본이 막힌다. **둘 중 하나는 있어야 하고, 둘 다 없으면 막는다.**
표본이 둘이다: `examples/summary.sample.json`(객관식) · `examples/summary.seosulhyeong.sample.json`(서술형).

> 요약본이 받는 나머지 검사는 본편과 같다 — 빈 자리·총페이지·폰트·외부 의존·금지 문구·
> 쪽 표기·표기 쪽수=실제·쪽번호 일치·표 머리글·제목만 있는 장·본문 살아남음.
> 채움률은 「마지막 장을 뺀」 규칙에 따라 잴 장이 없으므로 **주의로 그 사실을 적는다.**

## 6. MD ↔ 리포트 대조 (`--md <폴더>`)

대조의 기준은 **언제나 `--exam <exam.json>`** 이다. `--md` 를 줬는데 `--exam` 이 없으면
**막는다** — `report.json` 의 값은 학부모에게 «보여 주는» 값이라 원값과 다를 수 있다.
서술형 정답이 문항표에서 «서술형» 으로 찍히는 것이 그 예다. 표시값으로 MD 를 나무라면
**표시 규칙이 하나 늘 때마다 오차단이 난다.** 말없이 report.json 으로 대신하지 않는다.

```bash
python scripts/gate_check.py out/ report.json --exam exam.json --md <md폴더>   # 이 꼴로 부른다
```

**꼴의 정본은 `references/md-contract.md` 다.** 아래는 게이트가 그 계약을 어떻게 재는지다.
계약이 바뀌면 이쪽을 고친다 — **규격을 두 벌로 들고 있지 않는다.**

| 검사 | 대상 | 차단 조건 | 계약 |
|---|---|---|---|
| **대조 기준이 exam.json** | 인자 | `--md` 를 줬는데 `--exam` 이 없다 | |
| 대조할 MD 존재 | 폴더 | `기출문제` · `기출정답해설` MD 가 하나도 없다 | |
| **읽을 파일이 하나씩** | 폴더 | 같은 낱말을 가진 파일이 둘 이상 | § 7 |
| 문항 제목 읽힘 | 두 파일 | «## 11번» / «## 11.» 꼴 제목을 하나도 못 찾았다 | § 1 |
| **번호 겹침 없음** | 두 파일 | 같은 번호가 두 번 나온다 (어느 쪽을 읽었는지 알 수 없다) | § 1 |
| 문항 번호 집합 일치 | 두 파일 | MD 번호 집합 ≠ exam 번호 집합 (빠진 것·더 있는 것 둘 다) | § 1 |
| 정답 / 배점 / 난이도 / 유형 **일치** | 해설 | 제목 줄 · `meta` 주석 · `exam.json` 셋 중 하나라도 어긋난다 | § 2 |
| 〃 **표기 존재** | 해설 | 제목 줄에 그 값이 없다 | § 2 |
| meta 주석 JSON | 해설 | `<!-- meta: {…} -->` 가 깨진 JSON 이다 | § 2 |
| **킬러문항 네 칸** | 해설 | `killer` 인데 정답 근거·오답 근거·푸는 순서·필요 개념 중 하나가 비었다 | § 3 |
| **issue 문항 이유** | 해설 | `issue/…` 인데 이유가 없다 | § 5 |
| **issue 갈래 닫힌 목록** | 해설 | 복수정답·조건누락·범위밖·배점과다·유형급변 밖의 갈래를 썼다 | § 5 |

### 읽는 방식

- 제목 줄: `## 11번  정답 ②  [5점] · 난이도 상 · 빈칸추론`
- meta 주석: `<!-- meta: {"no":11,"answer":"2","points":5,"difficulty":"상","type":"빈칸추론","flags":["killer"]} -->`
- **제목 줄과 meta 를 따로 읽어 각각 exam.json 과 맞춰 본다.** 둘을 합쳐 하나로 보면
  서로 어긋난 것을 영영 못 본다. 어긋나면 **어느 쪽이** 다른지 이름을 대고 말한다 —
  `9번 meta 주석 «5» ≠ exam.json «2»`
- **정답은 «배점 대괄호 앞까지» 가 전부다.** 서술형은 한 낱말이 아니라 문장이 통째로 온다 —
  `## 36번  정답 ask if your wish was to add an interactive element  [5점] · 난이도 상 · 서술형`.
  공백에서 끊으면 «ask» 만 읽고 「exam.json 과 다르다」며 막는다. 실제 기출(명지고2
  2026-1학기 기말)에서 서술형 넷이 그렇게 막혔고 **MD 가 맞고 게이트가 틀렸다.**
  자르는 자리는 `report_build.py` 의 `parse_title` 과 같다(`[` 와 `·`) —
  **규격을 두 벌로 들고 있지 않는다.** 겹친 공백은 같은 값으로 보되 **글자는 지우지 않는다**
- **복수정답 «3,4» 를 받는다.** 「어법상 틀린 것을 **두 개** 고르시오」는 내신에 흔하다.
  적는 차례는 사람마다 다르니 **집합으로 견준다** — «4,3» 도 «③,④» 도 같은 정답이다.
  대신 «3,5»(하나가 다름)·«3»(하나만 적음)은 그대로 막는다
- 정답은 `①~⑩` ↔ `1~10` 을 같은 것으로 본다. 서술형은 `본문참조` 처럼 글자 그대로
- 제목 줄의 `(추론 정답 — 학교 정답표 미확인)` 괄호는 정답·유형을 읽을 때 무시한다.
  다만 **그 말이 든 괄호만** 떼어 낸다 — 38번의 «(A) her dream / (B) …» 를 다치게 하지 않는다
- `killer` 판정 = `meta.flags` · exam 문항의 `flags` 에 `"killer"` **또는**
  `report.json` 의 `killer[]` 에 그 번호가 있다.
  **어느 쪽이든 한 번이라도 killer 로 불린 문항은 네 칸을 다 요구한다** (합집합).
  킬러 *선정* 이 옳은지는 재지 않는다 — 그건 `report_build.py` 가 난이도·배점으로 정한다
- 네 칸은 «칸 제목에서 다음 칸 제목까지» 로 자른다. 「다음 `**` 까지」로 자르면
  내용 안에 굵은 글씨(모범답안 등)가 한 번이라도 나올 때 그 칸이 빈 것처럼 보인다
- `issue` 판정 = `flags` 의 `issue/<갈래>` · `<!-- flag: issue/<갈래> — 이유 -->` 주석,
  또는 (옛 데이터) `issue` 필드 · `confidence:"low"` · `answer_source:"추론"`
- issue 의 「이유」 = `flag:` 주석의 이유 · `issue`(문자열) · `issue_reason` · `issue_note` · `note`,
  또는 MD 본문의 「이유 / 추론 정답 / ⟨판독불가⟩ / 미확인 / 확인 필요」.
  **`basis` 는 이유로 치지 않는다** — 그건 «유형 판정» 근거지 «이 문항이 수상한» 이유가 아니다.
  basis 를 이유로 치면 모든 문항이 이유를 가진 셈이 되어 검사가 죽는다

### 표본

`examples/samsung_h1_en/` (exam.json + 기출문제.md + 기출정답해설.md) 이 계약 표본이다.
게이트를 고칠 때마다 이 표본으로 **통과**를, 일부러 깨뜨린 사본으로 **차단**을 같이 본다.

```bash
python scripts/gate_check.py <out/> --exam examples/samsung_h1_en/exam.json \
                                    --md   examples/samsung_h1_en
```

## 7. 검사를 새로 지을 때

1. **먼저 깨뜨려 보라.** 일부러 깨뜨린 표본에서 실제로 차단이 찍히는지 보기 전에는
   그 검사를 믿지 않는다. 오늘도 「내용이 인쇄 상자 밖으로 나갔나」를 짰다가,
   크롬이 상자 밖을 아예 그리지 않는다는 걸 깨뜨려 보고서야 알았다 —
   그 검사는 영원히 0개를 재고 통과했을 것이다
2. **정상 표본이 계속 통과하는지 같이 보라.** 막기만 하는 게이트는 꺼진다
3. **못 쟀으면 못 쟀다고 적어라.** 말없는 통과가 가장 나쁘다
