# 공감에듀 기출 분석 리포트

시험지 한 벌을 받아 **여섯 개 파일**을 낸다. 리포트 한 장으로 끝내지 않는다 —
읽어낸 내용이 파일로 남아야 다음 자료에 재투입된다.

| # | 파일 | 무엇 |
|---|---|---|
| 1 | `…_문제.md` | 문항 원문 (표·도표·보기 포함) |
| 2 | `…_정답해설.md` | 정답 + 해설 + 오답 근거 |
| 3 | `…_분석_유형별.md` | 유형 분포 · 유형별 정오 경향 |
| 4 | `…_분석_출제별.md` | 출제 단원·범위·교재 출처 매핑 |
| 5 | `…_분석_난이도별.md` | 난이도 분포 · 변별 문항 · 킬러문항 |
| 6 | `…_리포트.html` + `.pdf` | 학원 브랜딩 A4 리포트 |

> **공용 규격 상속** — 파일명·2종 원칙은 `gonggam-material-studio/reference/output-conventions.md`,
> 폰트·판형은 같은 곳 `print-spec.md` 를 따른다. 충돌하면 그쪽이 우선한다.

## 0. 이 스킬의 설계 원칙 — 무엇을 누가 하는가

**Claude Opus 를 쓴다는 전제로 짜여 있다.** 그래서 분업이 이렇게 갈린다.

| 일 | 누가 | 왜 |
|---|---|---|
| 시험지 판독 (사진·스캔 포함) | **Opus 비전** | 외부 OCR 엔진보다 표·수식·밑줄 문맥을 잘 읽는다 |
| 유형 분류 · 난이도 판정 | **Opus** | 판단이다. 규칙표로 안 떨어진다 |
| **킬러문항 선별** | **기계** | 난이도 `상` 중 배점순 · 동점이면 번호순 · 최대 5. 규칙이라 매번 같아야 한다 |
| **이슈문항 판정** | **사람(강사)** | 복수정답·조건누락은 기계도 Opus 도 못 잡는다. 가르친 사람만 안다 |
| 번호 매기기 · 총페이지 · 조판 · 치환 | **렌더러(`render_report.py`)** | 기계가 셀 일을 사람이 세면 틀린다 |
| 발행 가부 | **게이트(`gate_check.py`)** | 사람이 「됐다」고 말하는 걸 믿지 않는다 |

### ⛔ Claude 는 HTML 을 직접 쓰지 않는다

이 스킬에서 **가장 중요한 금지**다.

```
✗ 옛 방식 : Claude → 파이썬 f-string 으로 HTML 조립 → 수식 깨짐 → 사후 복구 함수
✓ 이 방식 : Claude → report.json  →  render_report.py  →  HTML  →  PDF
```

f-string 안에서 `\frac` 은 폼피드가 되고 `\angle` 은 벨 문자가 된다.
그걸 나중에 치환해서 되돌리는 구조는 **증상만 가린다.**
문자열 조립을 아예 거치지 않으면 깨질 경로가 사라진다.

같은 이유로 섹션 번호·총페이지·정답 개수도 Claude 가 세지 않는다. 렌더러가 센다.

## 1. 파이프라인

```
[시험지 투입]  PDF · 사진 · 스캔  (HWP 원본이 있으면 그게 1순위)
      ↓
Stage 1  판독 → exam.json
      ↓
         ❓ Q1 시험 정보 맞나  ┐
         ❓ Q2 무엇을 만드나   │ 한 화면에 묶어 묻는다
         ❓ Q3 디자인          │
         ❓ Q4 넣을 섹션      ┘
         ❓ Q5 흐린 문항이 있으면 — 다시 찍기 / 그대로 / 제외
      ↓
Stage 2  분석 (과목 스킬 게이트 통과)
      ↓
         ❓ Q6 킬러문항 확정 + 이슈문항 (강사만 안다)
      ↓
Stage 3  MD 5종 출력            ← 여기가 본체다. 리포트는 여기서 파생된다
      ↓
Stage 4  exam.json + MD → report.json → 렌더 → 요약본 1장 / 상세본
      ↓                                 ❓ Q7 등급컷을 켤 때만
Stage 5  게이트 + 학원 광고 검수  → 통과해야 전달
```

## 2. 문진 — 갈림길에서만, 선택지를 주고 묻는다

> **규격 정본은 `references/asking.md` 다.** 묻는 자리 일곱과 선택지가 거기 있다. 먼저 읽는다.

**자유 입력으로 받지 않는다. `AskUserQuestion` 으로 선택지를 준다.**
원장님은 고르기만 하면 되고, 우리는 받은 값이 규격 안에 있음을 보장받는다.

| # | 언제 | 무엇 |
|---|---|---|
| **Q1** | 판독 직후 | 시험 정보가 맞는지 (읽어 보여주고 확인만) |
| **Q2** | Q1 직후 | 무엇을 만들지 — 요약본 / 상세본 / **둘 다**(기본) |
| **Q3** | Q2 직후 | **디자인** — clean · gonggam · mono · warm · **우리 학원 색으로** |
| **Q4** | Q3 직후 | 넣을 섹션 (상세본일 때만 · 복수 선택) |
| **Q5** | 흐린 문항이 있을 때 | 다시 찍기 / 그대로(표시 남김) / 제외 |
| **Q6** | 분석 끝난 뒤 | 킬러문항 확정 + **이슈문항**(강사만 안다) |
| **Q7** | 등급컷을 켤 때만 | 표본·기간·출처 — 셋 없으면 켜지 않는다 |

**Q1~Q4 는 한 화면에 묶어 묻는다.** 네 번 나눠 물으면 3회차쯤에 지친다.
나머지는 그 단계에 도달했을 때만.

### 디자인은 반드시 묻는다 (Q3)

한 번 정하면 그 학원의 **모든 리포트**가 그 색으로 나간다. 내가 고르지 않는다.

「우리 학원 색으로」를 고르면 **색 두 개만** 받고 나머지 변수는 기계가 파생시킨다
(주색 → `--primary-pale` · `--cover-bg`, 강조색 → `--accent-pale`).
결과는 `assets/themes/<학원명>.css` 로 저장하고 **다음부터 안 묻는다.**

대비가 **4.5:1 미만**이거나 흑백 변환 시 두 색의 명도 차가 **20% 미만**이면 되묻는다 —
학원 문서는 복사기를 거친다. 색만으로 구분하면 사라진다.

### 묻지 않는 것

문항의 유형·난이도(스킬이 판정한다) · 쪽수와 섹션 번호(기계가 센다) · 파일 이름(규격이 정한다) ·
폰트(바꾸면 쪽수가 달라진다) · **「이 정도면 됐나요?」**(게이트가 판정한다. 사람에게 떠넘기지 않는다).

## 3. Stage 1 — 판독

### 3-1. 입력 갈래

| 입력 | 처리 |
|---|---|
| 텍스트 PDF | 그대로 읽는다 |
| 스캔 PDF (이미지) | 페이지를 이미지로 뽑아 비전으로 읽는다 |
| 사진 (휴대폰 촬영) | 비전으로 직접 읽는다. 기울기·그림자 감안 |

사진은 **장당 한 면**이 원칙이다. 한 장에 두 면이 들어오면 나눠 달라고 요청한다 —
쪼개진 문항 번호가 섞이면 뒤의 분석이 전부 어긋난다.

### 3-2. 판독 결과 = `exam.json`

문항마다 아래를 채운다. **모르는 것을 지어내지 않는다.**

```json
{
  "meta": {"school":"명지고","grade":"H1","term":"2026-1학기 중간","subject":"영어",
           "total_items":25,"total_points":100},
  "items":[
    {"no":1,"type":"객관식","points":3,"stem":"…","choices":["…"],
     "answer":"3","source":"교과서 2과","confidence":"high"}
  ]
}
```

**`confidence` 는 의무 필드다.** 글자가 뭉개졌거나 잘렸거나 그림이 필요한데 안 보이면
`"low"` 로 적고 `"note"` 에 무엇이 안 보이는지 쓴다.
게이트가 `low` 를 세어서 **원장님께 되묻게 만든다.** 조용히 넘어가지 않는다.

### 3-3. 정답을 모를 때

정답표가 시험지에 없으면 **풀어서 낸다.** 단 그렇게 낸 정답은
`"answer_source":"추론"` 으로 표시하고, 리포트에도 그 표시가 남는다.
학교 정답표가 따로 있으면 그걸 받아 덮어쓴다.

## 4. Stage 2 — 분석 (과목 스킬 게이트)

### 4-1. 과목이 정해지면 열 스킬이 자동으로 정해진다

`gonggam-material-studio/reference/skill-gates.md` 의 원칙을 그대로 쓴다 —
**연결을 사람의 판단에 맡기지 않는다.**

| 과목 | 반드시 여는 스킬 |
|---|---|
| **영어** | `gonggam-solving-logic:gonggam-daeui-reading` · `gonggam-binkan-inference` · `gonggam-order-logic` · `gonggam-grammar-golden` · `gonggam-voca-taxonomy` |
| **수학** | `gonggam-math-engine` (문항 대조·쌍둥이 탐색) |
| **국어** | 없음 — §5 `references/subject-axes.md` 의 국어 축을 쓴다 |
| **과학** | 없음 — 같은 파일의 과학 축을 쓴다 |

영어 문항을 유형 분류하면서 위 스킬을 열지 않으면 **분류 근거가 즉흥이 된다.**
실제로 옛 스킬이 그랬다. 근거를 `analysis.json` 에 남긴다.

```json
{"no":18,"type":"빈칸추론","basis":"binkan:원칙1 맥락 — 03번 주제문을 되풀이하는 자리"}
```

`basis` 없이 유형만 적힌 문항이 있으면 **게이트에서 막힌다.**

### 4-2. 과목별 분석축

과목마다 «무엇으로 쪼개 보는가» 가 다르다. 정본은 `references/subject-axes.md`.

| 과목 | 유형축 | 출제축 | 난이도축 |
|---|---|---|---|
| 영어 | 대의·빈칸·순서삽입·어법·어휘·세부내용·서술형 | 교과서 과 / 부교재 / 모의고사 지문 | Lexile · 선지 매력도 · 오답률 추정 |
| 수학 | 계산·이해·추론·문제해결 | 대단원 → 중단원 | 풀이 단계 수 · 개념 결합 수 |
| 국어 | 화법·작문·문법·문학·독서 | 작품/제재명 | 지문 길이 · 추론 깊이 |
| 과학 | 개념·자료해석·탐구설계·계산 | 대단원 → 소단원 | 자료 수 · 변인 수 |

난이도는 **상·중상·중·중하·하 5단**으로 통일한다. 과목이 달라도 리포트 표는 같은 칸을 쓴다.

## 5. Stage 3 — MD 5종

규격 정본은 `references/md-outputs.md`. 요점만:

- **MD 는 리포트의 부산물이 아니라 본체다.** 리포트는 그중 일부를 보기 좋게 한 것뿐이다
- 문항 원문은 **손대지 않는다.** 맞춤법도 고치지 않는다 — 기출은 기출대로 남긴다
- 표·도표는 마크다운 표로, 수식은 `$…$` 로 남긴다
- 파일 머리에 `meta` 프런트매터를 붙인다. 이게 있어야 나중에 DB 로 긁힌다

```markdown
---
school: 명지고
grade: H1
term: 2026-1학기 중간
subject: 영어
items: 25
points: 100
built: 2026-09-20
---
```

**이 다섯 파일이 쌓이면 학교별 기출 DB 가 된다.** 변형문제·분석지·동형모의고사가
여기를 읽어 간다. 그래서 파일명과 프런트매터 규격을 어기면 안 된다.

## 6. Stage 4 — 리포트 렌더

### 6-1. 한 줄로 끝난다

```bash
python scripts/render_report.py report.json out/
```

렌더러가 하는 일 — Claude 가 하지 않는 일이다:

1. 고르지 않은 섹션을 `<!-- SECTION:xxx -->` 마커째 **실제로 제거**
2. 남은 섹션에 **번호를 다시 매긴다** (1,2,3… 결번 없이)
3. **총페이지를 센다** — `{{TOTAL_PAGES}}` 를 사람이 세지 않는다
4. 로고를 base64 로 박고, 밝은 로고면 흰 박스로 감싼다
5. `{{…}}` 치환 후 **남은 플레이스홀더가 있으면 렌더를 실패시킨다**

### 6-2. 디자인 버전

`assets/themes/` 안의 css 를 갈아끼운다. 템플릿은 하나, 테마는 여럿이다.

| 테마 | 성격 | 언제 |
|---|---|---|
| `clean` | 흰 바탕 · 남색 | 기본. 학부모 배포 |
| `gonggam` | 공감 민트·에메랄드 | 공감에듀테크 자체 발행 |
| `mono` | 무채색 | 흑백 복사 전제 (§ 학원 문서는 복사기를 거친다) |
| `warm` | 아이보리 · 브라운 | 초등·중등 학부모 |

새 학원 브랜드는 테마 파일 하나를 더 만드는 것으로 끝난다. **템플릿은 건드리지 않는다.**

### 6-3. PDF 변환

```bash
python scripts/render_pdf.py out/리포트.html out/리포트.pdf
```

- **헤드리스 크롬 `--print-to-pdf`** 를 쓴다. Windows·리눅스 양쪽에서 크롬/엣지를 탐색한다
- `print-spec.md` 는 교재에 Paged.js 를 요구하지만 **리포트는 예외다** —
  끼우면 비동기 대기라는 사고 지점만 새로 생긴다. 대신 **재서 넣는다**(아래).
- **PyMuPDF 가 필수다.** 쪽수를 재고 쪽번호를 찍는다. 없으면 조용히 넘어가지 않고 막는다

### 6-4. 쪽 나눔 — 추측하지 않는다

옛 방식은 「한 장에 20행」 같은 상수로 표를 미리 쪼갰다. **내용이 조금만 길어지면 깨졌다** —
표기 12쪽 / 실제 13쪽이 나왔고, 짧은 섹션도 한 장을 통째로 먹어 채움률이 35% 였다.

지금은 **섹션이 그냥 흐른다.** 잘리면 안 되는 것만 CSS 불가분 단위로 묶는다 —
표의 행 · 표 머리글 반복 · 카드 · 콜아웃 · 제목+본문 · 고아/과부 2줄 · 그림+캡션.

쪽번호는 **실제 PDF 를 재서** 넣는다.

```
1패스   쪽번호 자리에 고정폭 «00 / 00» → 렌더 → PDF
측정    PyMuPDF 로 총 쪽수와 각 섹션이 시작하는 쪽을 읽는다
2패스   진짜 숫자를 넣어 다시 렌더 → 다시 재서 «쓴 값 == 잰 값» 확인
        수렴 못 하면 (최대 4패스) 렌더를 실패시킨다
장번호  크로미움은 @page 쪽번호를 지원하지 않는다. 조판이 끝난 뒤
        기계가 장을 세어 오른쪽 아래에 찍고, 찍은 자리를 다시 재서 검사한다
```

실측: **12쪽 → 6쪽, 채움률 36% → 82%.** 상수는 하나도 남지 않았다.
- **폰트는 동봉 woff2 만 쓴다.** 시스템 폰트명을 CSS 에 적지 않는다 —
  PC 마다 글자폭이 달라져 쪽수가 달라진다. 폰트가 없으면 **렌더를 막는다**

## 7. Stage 5 — 게이트 (통과 못 하면 전달하지 않는다)

```bash
python scripts/gate_check.py out/
```

| 검사 | 실패 조건 |
|---|---|
| 플레이스홀더 | `{{` 가 하나라도 남음 |
| 섹션 번호 | 결번·중복 |
| 페이지 수 | 표기된 총페이지 ≠ 실제 `.page` 수 |
| 판독 신뢰도 | `confidence:"low"` 문항이 있는데 원장님 확인 기록이 없음 |
| 유형 근거 | `basis` 없는 문항 존재 |
| 정답 정합 | 정답 개수 ≠ 문항 수 / 선지 범위 밖 정답 |
| 배점 합 | 배점 합계 ≠ 총점 |
| 폰트 | 동봉 woff2 없음 |
| PDF | 0바이트 · 페이지 0 · 본문 미렌더 |
| 금지 문구 | 「100%」「무조건」「보장」「1위」「적중」 |

**게이트는 경고하지 않는다. 막는다.** 옛 스킬은 수식이 0개로 렌더돼도 「성공」을 찍었다.

### 7-1. 학원 광고 검수

리포트가 **학원 이름으로 학부모에게 나가는 문서**라면 `academy-compliance` 를 통과시킨다.
내부 참고용이면 생략한다. 어느 쪽인지 애매하면 **통과시키는 쪽**을 고른다.

### 7-2. 예상 등급컷 — 기본으로 끈다

옛 스킬은 학교 수준에 따라 등급컷을 「+10~15점」씩 보정했다. **그 숫자에 근거가 없다.**
근거 없는 숫자가 학원 이름으로 학부모에게 나가면 표시광고법 문제가 된다.

- 기본값 **끄기**
- 켜려면 산출 근거(표본·기간·출처)를 함께 받는다
- 리포트에는 언제나 **「예상치이며 실제와 다를 수 있습니다」** 와 산출 기준을 같이 박는다

## 8. 파일명

`output-conventions.md` 의 꼴을 따른다. 종류는 `기출분석리포트`·`기출문제`·`기출정답해설`·`기출분석`.

```
공감에듀_기출분석리포트_H1_명지고_2026-1학기중간_영어.pdf
공감에듀_기출문제_H1_명지고_2026-1학기중간_영어.md
공감에듀_기출분석_H1_명지고_2026-1학기중간_영어_난이도별.md
```

**이름을 손으로 짓지 않는다.** `scripts/outname.py` 가 짓고 게이트가 검사한다.

공용 규격의 **학생용/교사용 2종**은 이 스킬에서 이렇게 옮겨 붙는다.

| 종 | 누구 | 무엇이 빠지나 |
|---|---|---|

| **내부본** | 원장·강사 | 전부 포함. 판독 신뢰도·유형 판정 근거까지 |

레이아웃은 **완전히 같다.** 배포본이라고 페이지가 밀리면 안 된다.

## 10. 하지 않는 것

1. **문항을 새로 출제하지 않는다** — 그건 `gonggam-material-studio` 계열이다
2. **HTML 을 손으로 쓰지 않는다** (§0)
3. **번호·페이지수를 세지 않는다** — 렌더러가 센다
4. **모르는 것을 지어내지 않는다** — `confidence:"low"` 로 남기고 되묻는다
5. **근거 없는 숫자를 리포트에 싣지 않는다** — 등급컷·정답률·적중률 전부
6. **시스템 폰트를 쓰지 않는다** — 쪽수가 PC 마다 달라진다
7. **게이트를 건너뛰지 않는다** — 「이번만」이 규격을 무너뜨린다
